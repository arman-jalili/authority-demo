# authority-demo — Agent Guidelines

Same repo, two audiences:

- **Coding agents**: read [`CLAUDE.md`](./CLAUDE.md). It is the operative
  instruction set — what you may do freely, and what you must hand to Rigorix.
- **Humans**: read [`README.md`](./README.md).

## Rules

1. **Money moves through Rigorix, never through a direct tool call.** The
   `PreToolUse` hook (`.claude/hooks/deny-ledger-tamper.mjs`) blocks direct
   payout execution and ledger writes. Do not try to work around it.
2. **The authority is not yours to change.** `authority.json` and the check
   that reads it live OUTSIDE this repository
   (`$HOME/.rigorix-authority-demo`). Freezing and thawing are **operator**
   actions; a permission rule denies agent writes to them.
3. **Never edit `.rigorix/**`.** The gate config, the runbook, and the scripts
   are operator config. `.rigorix/preconditions.toml` is generated by
   `setup-authority.sh` — never hand-edit it.
4. **Read-only inspection is sanctioned** (`list_ledger.sh`,
   `show_authority.sh`). Use them to inspect state instead of touching files.
5. **The signed trail is evidence.** `.rigorix/audit` is what proves the
   refusal happened; do not delete it.
6. **An approval is not the same as a permission.** A run that is approved can
   still be refused at dispatch if the authority no longer holds. That is the
   feature, not a bug.
